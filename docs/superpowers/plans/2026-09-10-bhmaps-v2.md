# BhMaps v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn BhMaps into a map-first manager: every Brawlhalla map shown as an exact composed preview built from the game's own encrypted level data, under its real in-game name, with a universal background library, per-map platform sets, stacking packs, an exact `Default`-pack reset, and a rebuilt dark Fluent UI.

**Architecture:** `BhMaps.Core` gains four new areas — `LevelData/` (SWZ container decryption, SWF key discovery, level XML parsing, a stamped disk cache), `Maps/` (folding level data onto the game tree, per-map status), `Imaging/` (a pure `DrawingVisual` compositor plus an STA render thread and a JPEG disk cache), and new `Operations/` (Default pack, map reset, background apply, platform-set apply, export, undo, picture import). `BhMaps.App` keeps its no-DI composition root (`AppServices`) and its single-busy-operation boundary (`MainViewModel.RunBusyAsync`), and replaces the v1 window with a sidebar shell hosting six pages. Core is unit tested with xunit; the WPF layer is verified by hand against the dev tree.

**Tech Stack:** .NET SDK 10.0.300, C# 14, WPF on `net10.0-windows`, `ThemeMode="Dark"` (Fluent), CommunityToolkit.Mvvm 8.4.2, xunit 2.9.3, `System.IO.Compression.ZLibStream`, `System.Text.Json` / `System.Text.Json.Nodes`, `System.Xml.Linq`, WPF imaging.

**Spec:** `docs/superpowers/specs/2026-09-10-bhmaps-v2-design.md` (v2 — wins over everything else). Its section numbers are cited below as "spec 3.2" etc. The v1 spec `docs/superpowers/specs/2026-09-08-bhmaps-design.md` still governs scan, hashing, v1 status, apply, v1 reset, import routing, background fit, settings storage, safety rules and testing tiers, except where v2 changes them. The verified reference port of the container format is `docs/superpowers/reference/swz.py`.

## Decisions this plan makes where the spec left a choice open

An implementer must **not** re-litigate any of these.

| # | Question the spec left open | Decision |
|---|---|---|
| D1 | Attribute vs child element for `LevelName`, `AssetDir`, `CameraBounds`, `Background` in `LevelDesc_*.xml` | The parser reads each from **an attribute or a same-named child element, whichever is present**. Costs three lines and cannot be wrong either way. |
| D2 | Which XML elements form the platform tree | Recursive walk of **every** child element. An element named `Asset` is a leaf; anything else (`Platform`, `MovingPlatform`, unknown) is a transform node reading `X/Y/Scale/ScaleX/ScaleY/Rotation/Theme` from its attributes, absent attributes meaning identity. Uniform, and covers `MovingPlatform` which the spec does not mention. |
| D3 | Transform order inside a platform node | **Scale, then rotate, then translate** (`TransformGroup` children in that order). Rotation is degrees. |
| D4 | What a negative `W`/`H` flip mirrors about | The asset's **own centre**: draw into `Rect(X, Y, abs(W), abs(H))` under a `ScaleTransform(signW, signH, X + abs(W)/2, Y + abs(H)/2)`. |
| D5 | Who owns the STA render thread | A Core class `BhMaps.Core.Imaging.RenderQueue : IDisposable` — one dedicated `Thread` with `ApartmentState.STA` running a `Dispatcher`, exposing `Task<T> RunAsync<T>(Func<T>)`. `AppServices` constructs exactly one and disposes it on shutdown. `MapCompositor.Render` itself stays a pure static callable from any thread, so tests exercise it directly on the MTA test thread (already proven by `BackgroundFitter`). |
| D6 | Preview cache key string | `sha256_lowerhex(UTF8( levelName + "|" + width + "x" + height + "|" + join("|", inputName + ":" + sha256(inputFile)) ))` over the resolved input files **in draw order, background first**. Hashes come from the existing `HashCache`. |
| D7 | "Unused cache files older than 30 days" | Track by `LastWriteTimeUtc`; a cache **hit touches the file** (`File.SetLastWriteTimeUtc(path, DateTime.UtcNow)`). `LastAccessTime` is unreliable on Windows. |
| D8 | Map status summary precedence | `Missing` beats `Custom` beats pack names beats `Default`. Missing is the only coloured state. |
| D9 | `PictureImporter` fit modes — the spec maps four labels onto only three fitter behaviours (`Center` and `Fit` both "Contain") | `Stretch` maps to `FitMode.Stretch`; `Fill` to `FitMode.Cover`; `Fit` to `FitMode.Contain`; **`Center` to `FitMode.Contain` with a new additive `FitOptions.NoUpscale = true`** so a source smaller than 2048x1151 is centred at 1:1 instead of blown up. `NoUpscale` defaults to `false`, so every existing `BackgroundFitter` behaviour and test is untouched. Reverting to the literal spec is a one-line change in `PictureImporter.ToFitOptions`. |
| D10 | How pages are hosted in the main window | `MainWindow` is a two-column `Grid`: fixed 240 px sidebar, then a `ContentControl Content="{Binding CurrentPage}"`. `App.xaml` holds one implicit `DataTemplate` per page view model mapping it to its `UserControl`. `MainViewModel` **is** the navigation service (`CurrentPage` plus `NavigateXxx` commands); no separate interface, no DI container. |
| D11 | Where the per-page header lives | A shared `Views/Controls/PageHeader.xaml` `UserControl` with `Title` and `Actions` dependency properties, used as the first child of every page's root `DockPanel`. It renders the busy/progress/done/Undo line itself by binding to the window's `DataContext` through `{RelativeSource AncestorType=Window}` — that is, to the shell `MainViewModel` — so busy state appears in the header without any template-selector machinery. |
| D12 | How the search autocomplete is built | Plain WPF only: `Views/Controls/SuggestBox.xaml` is a `Grid` holding a `TextBox` and a `Popup` (`Placement=Bottom`, `StaysOpen=False`, width bound to the TextBox) containing a `ListBox`. Dependency properties `Text`, `Suggestions`, `Placeholder`, `ChooseCommand`. Code-behind handles `PreviewKeyDown`: Down/Up move the list selection, Enter invokes `ChooseCommand` with the selected item or the first item, Escape closes. No third-party control, no editable `ComboBox` hackery. |
| D13 | Shell class name | The shell view model **keeps the name `MainViewModel`** with `RunBusyAsync`, `RescanAsync` and the busy boundary intact; its v1 grid and pack-list members are deleted. Renaming would break the one contract everything already relies on. |
| D14 | Dev tree layout | `make-dev-tree.ps1` restructures to `<dest>\game\mapArt\<Folders>` with the four data files at `<dest>\game\`, because the app derives the game **root** as the parent of the configured `mapArt` path. `--game` therefore points at `<dest>\game\mapArt`. |
| D15 | `whileRunning` unknown values | Any value other than `live` loads as `restart`. |
| D16 | Undo target list | Core operations do not compute undo lists. The App call site passes the relative paths it is about to write through `UndoSession.Capture(gamePath, relativePaths)`. `Pack` gains a computed `RelativePaths` property so "apply all" is one expression. |

```csharp
private static readonly string[] KnownKeys =
    ["gamePath", "libraryPath", "firstRunDone", "homeZoom", "backgroundsZoom", "whileRunning", "welcomeDone"];

public static AppSettings Load(string settingsPath)
{
    JsonObject? obj = null;
    if (File.Exists(settingsPath))
    {
        try
        {
            obj = JsonNode.Parse(File.ReadAllText(settingsPath)) as JsonObject;
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException or JsonException)
        {
```

```csharp
using System.Buffers.Binary;

namespace BhMaps.Core.LevelData;

/// <summary>WELL512-style PRNG the SWZ container is keyed with.
/// Port of docs/superpowers/reference/swz.py.</summary>
public sealed class SwzRandom
{
    private readonly uint[] _state = new uint[16];
    private int _index;

    public SwzRandom(uint seed)
    {
        _state[0] = seed;
        for (var i = 1; i < 16; i++)
        {
            var previous = _state[i - 1];
            _state[i] = (uint)i + (0x6C078965u * (previous ^ (previous >> 30)));
        }
    }

    public uint Next()
    {
        var s = _state;
        var i = _index;
        var a = s[i];
        var b = s[(i + 13) % 16];
        var c = a ^ (a << 16) ^ b ^ (b << 15);
        b = s[(i + 9) % 16];
        b ^= b >> 11;
        s[i] = b ^ c;
        a = s[i];
        var d = a ^ ((a << 5) & 0xDA442D24u);
        i = (i + 15) % 16;
        a = s[i];
        s[i] = a ^ (a << 2) ^ (b << 28) ^ c ^ (c << 18) ^ d;
        _index = i;
        return s[i];
    }
}

public static class SwzKey
{
    public const uint ChecksumSeed = 0x2DF4A1CD;

    public static bool Check(ReadOnlySpan<byte> header, uint key, out SwzRandom rng)
    {
        var expected = BinaryPrimitives.ReadUInt32BigEndian(header);
        var seed = BinaryPrimitives.ReadUInt32BigEndian(header[4..]) ^ key;
        rng = new SwzRandom(seed);
        var checksum = ChecksumSeed;
        var rounds = (key % 31) + 5;
        for (var i = 0u; i < rounds; i++)
        {
            checksum ^= rng.Next();
        }

        return checksum == expected;
    }
}
```

- [ ] **Step 4: Implement the test-side encryptor `SwzWriter`**

This is the mirror of the reader. **It was verified against `swz.py`'s `read_swz` on 2026-09-10: a container built this way round-trips exactly.** The order of PRNG draws is load-bearing: `csize`, `usize`, the checksum seed, then one draw per byte. The entry checksum is **not** XORed with the PRNG and accumulates over the *compressed* (pre-obfuscation) bytes, so the whole loop must run before the header is written.

```csharp
using System.Buffers.Binary;
using System.IO.Compression;
using System.Numerics;
using BhMaps.Core.LevelData;

namespace BhMaps.Core.Tests.Helpers;

/// <summary>Builds a .swz container the way the game does, so SwzReader can be
/// round-tripped without the real files.</summary>
public static class SwzWriter
{
    public static byte[] Write(uint key, IReadOnlyList<byte[]> entries, uint seedWord = 0x12345678)
    {
        var output = new MemoryStream();
        var header = new byte[8];
        var rng = new SwzRandom(seedWord ^ key);
        var checksum = SwzKey.ChecksumSeed;
        var rounds = (key % 31) + 5;
        for (var i = 0u; i < rounds; i++)
        {
            checksum ^= rng.Next();
        }

        BinaryPrimitives.WriteUInt32BigEndian(header, checksum);
        BinaryPrimitives.WriteUInt32BigEndian(header.AsSpan(4), seedWord);
        output.Write(header);

        foreach (var raw in entries)
        {
            var compressed = Deflate(raw);
            WriteU32(output, (uint)compressed.Length ^ rng.Next());
            WriteU32(output, (uint)raw.Length ^ rng.Next());

            var body = new byte[compressed.Length];
            var accumulator = rng.Next();
            for (var i = 0; i < compressed.Length; i++)
            {
                var random = rng.Next();
                var bitIndex = i & 0xF;
                var mask = (byte)((((0xFFu << bitIndex) & random) >> bitIndex) & 0xFF);
                body[i] = (byte)(compressed[i] ^ mask);
                accumulator = compressed[i] ^ BitOperations.RotateRight(accumulator, (i % 7) + 1);
            }

            WriteU32(output, accumulator);
            output.Write(body);
        }

        return output.ToArray();
    }

    public static byte[] Deflate(byte[] raw)
    {
        var buffer = new MemoryStream();
        using (var zlib = new ZLibStream(buffer, CompressionLevel.Optimal, leaveOpen: true))
        {
            zlib.Write(raw);
        }

        return buffer.ToArray();
    }

    private static void WriteU32(Stream stream, uint value)
    {
        Span<byte> four = stackalloc byte[4];
        BinaryPrimitives.WriteUInt32BigEndian(four, value);
        stream.Write(four);
    }
}
```

**Algorithm (spec 3.2).** After `SwzKey.Check` succeeds, `offset = 8`; while `container.Length - offset > 12`:

```
csize = u32be(offset)     ^ rng.Next();  offset += 4
usize = u32be(offset)     ^ rng.Next();  offset += 4
entryChecksum = u32be(offset);           offset += 4
cs = rng.Next()
for i in 0 .. csize-1:
    rnd = rng.Next()
    bi  = i & 0xF
    b   = container[offset + i] ^ (byte)(((0xFF << bi) & rnd) >> bi)
    buf[i] = b
    cs  = b ^ RotateRight(cs, (i % 7) + 1)
offset += csize
if cs != entryChecksum -> InvalidDataException
raw = ZLibStream(buf) inflated; raw.Length must equal usize
```

**Algorithm (spec 3.3).**

- Signature: `FWS` means the body is bytes `[8..]`; `CWS` means `ZLibStream` over bytes `[8..]`; `ZWS` is **unsupported**, so `Find` returns `new KeySearchResult(null, 0, "This BrawlhallaAir.swf uses LZMA compression, which BhMaps does not read.")`.
- Skip the header RECT: `nbits = body[0] >> 3`; `total = 5 + 4 * nbits`; `offset = (total + 7) / 8`; then `offset += 4` for framerate (2 bytes) and frame count (2 bytes).
- Tag loop: `th = u16le`; `code = th >> 6`; `len = th & 0x3F`; if `len == 0x3F` then `len = u32le`. Yield `(code, body[offset .. offset+len])`, then `offset += len`.
- Candidate ABC blobs: tag code **72** is raw ABC; tag code **82** is 4 bytes of flags, then a NUL-terminated name, then ABC, so take everything after the first `0x00` at index 4 or later. The reference handles both codes even though the spec names only 82; implement both.
- ABC uint pool: `offset = 4` (minor u16 plus major u16); read `intCount` as u30 and skip `max(0, intCount - 1)` u30s; read `uintCount` as u30 and read `max(0, uintCount - 1)` u30s. Those are the candidates.
- u30 decode: accumulate `r |= (uint)(c & 0x7F) << sh`, stopping when the continuation bit is clear **or** `sh >= 28`. A value at or above 2^28 uses five bytes and the top three bits are discarded by the shift, exactly as the reference does.
- For each candidate uint in order, call `SwzKey.Check` against the SWZ's first 8 bytes only. First hit wins. A malformed ABC blob is skipped, not fatal.
- The key found on 2026-09-09 was **826351010**. It changes with every game update. **Never hard-code it in product code**; it appears only in tests.

```csharp
using System.Buffers.Binary;
using System.IO.Compression;

namespace BhMaps.Core.Tests.Helpers;

/// <summary>Builds a minimal SWF whose single DoABC tag carries a constant pool holding the given uints.</summary>
public static class SwfWriter
{
    public static byte[] Uncompressed(IReadOnlyList<uint> uints) => Assemble("FWS"u8.ToArray(), Body(uints));

    public static byte[] Compressed(IReadOnlyList<uint> uints)
    {
        var body = Body(uints);
        var buffer = new MemoryStream();
        using (var zlib = new ZLibStream(buffer, CompressionLevel.Optimal, leaveOpen: true))
        {
            zlib.Write(body);
        }

        return Assemble("CWS"u8.ToArray(), buffer.ToArray());
    }

    public static byte[] Lzma() => Assemble("ZWS"u8.ToArray(), [0, 0, 0, 0]);

    private static byte[] Assemble(byte[] signature, byte[] body)
    {
        var output = new MemoryStream();
        output.Write(signature);
        output.WriteByte(13);                              // version
        var length = new byte[4];
        BinaryPrimitives.WriteUInt32LittleEndian(length, (uint)(8 + body.Length));
        output.Write(length);
        output.Write(body);
        return output.ToArray();
    }

    private static byte[] Body(IReadOnlyList<uint> uints)
    {
        var output = new MemoryStream();
        output.WriteByte(0x00);                            // RECT with nbits 0, so one byte
        output.Write([0x00, 0x0C, 0x01, 0x00]);            // framerate and frame count

        var abc = new MemoryStream();
        abc.Write([0x10, 0x00, 0x2E, 0x00]);               // minor 16, major 46
        abc.Write(U30(1));                                 // int_count 1, so no entries
        abc.Write(U30((uint)uints.Count + 1));             // uint_count
        foreach (var value in uints)
        {
            abc.Write(U30(value));
        }

        var tagBody = new MemoryStream();
        tagBody.Write([0x00, 0x00, 0x00, 0x00]);           // DoABC flags
        tagBody.Write("bhmaps"u8);
        tagBody.WriteByte(0x00);                           // name terminator
        tagBody.Write(abc.ToArray());

        var payload = tagBody.ToArray();
        var header = new byte[2];
        BinaryPrimitives.WriteUInt16LittleEndian(header, (ushort)((82 << 6) | 0x3F));
        output.Write(header);
        var longLength = new byte[4];
        BinaryPrimitives.WriteUInt32LittleEndian(longLength, (uint)payload.Length);
        output.Write(longLength);
        output.Write(payload);
        return output.ToArray();
    }

    private static byte[] U30(uint value)
    {
        var bytes = new List<byte>();
        while (true)
        {
            var b = (byte)(value & 0x7F);
            value >>= 7;
            if (value != 0)
            {
                bytes.Add((byte)(b | 0x80));
            }
            else
            {
                bytes.Add(b);
                break;
            }
        }

        return bytes.ToArray();
    }
}
```

```csharp
private static readonly string[] SkippedPrefixes = ["Small ", "Big ", "Tutorial"];

private static LevelDesc PickBase(string folder, IReadOnlyList<LevelDesc> levels, Func<LevelDesc, string> display)
{
    var named = levels.FirstOrDefault(l => l.LevelName.Equals(folder, StringComparison.OrdinalIgnoreCase));
    if (named is not null)
    {
        return named;
    }

    bool Eligible(LevelDesc l)
    {
        var name = display(l);
        return !SkippedPrefixes.Any(p => name.StartsWith(p, StringComparison.OrdinalIgnoreCase))
            && !MiniGameDisplayNames.Contains(name, StringComparer.OrdinalIgnoreCase);
    }

    var pool = levels.Where(Eligible).ToList();
    if (pool.Count == 0)
    {
        pool = levels.ToList();
    }

    return pool
        .OrderBy(l => display(l).Length)
        .ThenBy(display, StringComparer.OrdinalIgnoreCase)
        .First();
}
```

```csharp
    /// Never throws for a missing or bad asset; that asset is skipped.</summary>
    public static System.Windows.Media.Imaging.BitmapSource Render(

```

**Algorithm (spec 5), exact.**

1. Fill the whole `width` by `height` canvas with `#2F2D2B`.
2. `scale = min(width / camera.W, height / camera.H)`. The camera rectangle is centred:
   `offsetX = (width - camera.W * scale) / 2`, `offsetY = (height - camera.H * scale) / 2`.
   Push a clip to `Rect(offsetX, offsetY, camera.W * scale, camera.H * scale)`, then push a world transform
   `TransformGroup [ TranslateTransform(-camera.X, -camera.Y), ScaleTransform(scale, scale), TranslateTransform(offsetX, offsetY) ]`.
3. Draw the background stretched to the camera bounds: inside the world transform, `dc.DrawImage(bg, new Rect(camera.X, camera.Y, camera.W, camera.H))`. Only the **first** `Background` element is drawn.
4. Walk platforms depth-first. For each node:
   - **Skip the node and its whole subtree when `Theme` is present.** Seasonal art never appears.
   - Push `TransformGroup [ ScaleTransform(EffectiveScaleX, EffectiveScaleY), RotateTransform(Rotation), TranslateTransform(X, Y) ]`, which is scale then rotate then translate (decision D3).
   - Draw the node's assets, recurse into children, then pop.
   - Per asset: `w = abs(W)`, `h = abs(H)`; when `W < 0` or `H < 0`, push `ScaleTransform(W < 0 ? -1 : 1, H < 0 ? -1 : 1, X + w / 2, Y + h / 2)` (decision D4), draw into `Rect(X, Y, w, h)`, then pop. An asset whose `W` or `H` is 0 uses the decoded bitmap's pixel size instead.
   - An asset whose path resolves to nothing, or that fails to decode, is skipped silently.
5.
```csharp
using System.Windows.Threading;

namespace BhMaps.Core.Imaging;

/// <summary>One dedicated STA thread with a Dispatcher.
/// Composition never runs on the UI thread or the thread pool.</summary>
public sealed class RenderQueue : IDisposable
{
    private readonly Thread _thread;
    private readonly Dispatcher _dispatcher;
    private bool _disposed;

    public RenderQueue()
    {
        var ready = new TaskCompletionSource<Dispatcher>(TaskCreationOptions.RunContinuationsAsynchronously);
        _thread = new Thread(() =>
        {
            ready.SetResult(Dispatcher.CurrentDispatcher);
            Dispatcher.Run();
        })
        {
            IsBackground = true,
            Name = "BhMaps render",
        };
        _thread.SetApartmentState(ApartmentState.STA);
        _thread.Start();
        _dispatcher = ready.Task.GetAwaiter().GetResult();
    }

    public Task<T> RunAsync<T>(Func<T> work, CancellationToken ct = default)
    {
        ObjectDisposedException.ThrowIf(_disposed, this);
        return _dispatcher.InvokeAsync(work, DispatcherPriority.Normal, ct).Task;
    }

    public void Dispose()
    {
        if (_disposed)
        {
            return;
        }

        _disposed = true;
        _dispatcher.InvokeShutdown();
        _thread.Join(TimeSpan.FromSeconds(2));
    }
}
```

On a miss it awaits `queue.RunAsync(() => Encode(MapCompositor.Render(level, width, height, sources)), ct)` producing `byte[]`, writes to `<Root>\.<key>.<guid>.tmp` and calls `File.Move(temp, path, overwrite: true)`.

```csharp
public static bool CloseAndWait(TimeSpan? timeout = null)
{
    var deadline = DateTime.UtcNow + (timeout ?? CloseTimeout);
    var processes = Process.GetProcessesByName(ProcessName);
    try
    {
        foreach (var p in processes)
        {
            try
            {
                p.CloseMainWindow();
            }
            catch (Exception ex) when (ex is InvalidOperationException or System.ComponentModel.Win32Exception)
            {
                // Already gone, or no main window; the kill below covers it.
            }
        }

        foreach (var p in processes)
        {
            var remaining = deadline - DateTime.UtcNow;
            if (remaining > TimeSpan.Zero)
            {
                try
                {
                    p.WaitForExit((int)remaining.TotalMilliseconds);
                }
                catch (Exception ex) when (ex is InvalidOperationException or SystemException)
                {
                }
            }

            try
            {
                if (!p.HasExited)
                {
                    p.Kill(entireProcessTree: true);
                    p.WaitForExit(2000);
                }
            }
            catch (Exception ex)
                when (ex is InvalidOperationException or System.ComponentModel.Win32Exception or NotSupportedException)
            {
            }
        }
    }
    finally
    {
        foreach (var p in processes)
        {
            p.Dispose();
        }
    }

    return !IsRunning();
}
```

## Risks and open questions

1. **D1 and D2 are the one place this plan guesses about real data.** The real `Dynamic.swz` was not read, because the safety rule reserves that for the opt-in tests. The tolerant parser makes both XML shapes work, so the guess cannot produce a wrong result; but if the real `LevelDesc` uses an element shape this plan does not anticipate for platforms, Task 9's composite tests are the tripwire, and they run before any UI work. **This is the highest-value early signal in the plan. Do not defer Task 9.**
2. **`leveldata.json` size.** About 120 levels with full platform trees may serialize to several megabytes. It is written non-indented and atomically. If it exceeds roughly 20 MB in practice, the fix is to cache the decrypted XML instead of the model, but measure before changing anything.
3. **The `ThemeMode` experimental diagnostic.** `NoWarn WPF0001` is added defensively. If .NET 10 promoted `ThemeMode` out of experimental the `NoWarn` is harmless, and if it uses a different id the build fails loudly in Task 3 and the fix is to add that id.
4. **`RenderTargetBitmap` on the MTA test thread** is proven by the existing `BackgroundFitter` tests, which is why `MapCompositor.Render` stays a pure static and `RenderQueue` is tested separately. If a compositor test ever hangs, the cause is the test calling `RenderQueue`, not `Render`.
5. **Irreversibility.** `DefaultPack.Capture` deletes and replaces `packs\Default`; `PackDeleter.Delete` removes a pack; `MapReset` without a Default pack deletes game images. All three are confirm-gated in the UI, and only game-folder writes get an undo snapshot. **Library deletions are not undoable**, by design and by spec.
6. **Ordering constraint.** `UndoStore.Begin` deletes every earlier session, so it must be called **once per user action**, immediately before the write, never once per file. Calling it per file destroys the undo set mid-operation.
7. **Not verified.** The Steam library detection in Task 32, using the registry plus `libraryfolders.vdf`, is written blind against this machine's layout; its failure mode is a blank field the user fills with `Change`, which is acceptable. The running-game restart flow in Tasks 20 and 21 cannot be tested here at all and is the owner's manual step.

1. **csharpier versus `dotnet format`.** `dotnet csharpier --version` fails on this machine, csharpier is not installed, and the repo-root `.csharpierignore` holds a single `*` line whose stated purpose in the README is to disable an externally installed csharpier hook for this repo. **Chosen: `dotnet format BhMaps.slnx` as the sole formatter**, with an explicit "do not install csharpier" in Global Constraints.
2. **Fonts were already placed.** Commit `cc99b73` added the five Geist TTFs and OFL.txt under `src/BhMaps.App/Theme/Fonts/`, but they are **not** `<Resource>` items in the csproj, so they would not be embedded. Task 3 adds `<Resource Include="Theme\Fonts\*.ttf" />`. The TTF name tables give typographic families `Geist` and `Geist Mono`, so the pack URIs end `#Geist` and `#Geist Mono`.
3. **`SettingsStore` cannot preserve unknown fields today.** It round-trips through a fixed `SettingsFile` DTO, so spec section 8's "unknown fields are preserved on save" is a behaviour change rather than an addition. Task 1 replaces the DTO with `JsonNode` and adds `AppSettings.Unknown`.
4. **The dev tree layout was wrong for level data.** `make-dev-tree.ps1` currently makes `<dest>\game` *be* the `mapArt` folder, so the game root would resolve to `<dest>` and `-RealArt`'s data files would land outside the tree. **Chosen: restructure to `<dest>\game\mapArt`**, with `--game` pointing one level deeper. This changes the README's dev command in Task 34.
5. **`GameProcess` has no close.** Spec 6.7 needs "main window close, then terminate after ten seconds", so Task 20 adds `CloseAndWait`. It is the one piece with no unit test, because it cannot be tested without launching the real game, and it is verified only in the owner's manual step.
6. **`AtomicFile` has no `WriteAllBytes`.** The preview JPEG cache needs byte writes, so `PreviewCache` does its own temp-file-then-move rather than growing `AtomicFile` for a single caller.
7. **Spec 3.3 names only DoABC tag 82, but the verified reference also handles tag 72.** Chosen: implement **both**, matching `swz.py`.
8. **Spec 6.8's fit mapping is self-inconsistent**, putting four labels onto three fitter behaviours so that `Center` and `Fit` would do the same thing. Chosen: an additive `FitOptions.NoUpscale` for `Center` (decision D9), defaulting to `false` so no existing behaviour or test changes, with reverting to the literal spec being a one-line change.
9. **Spec 5 names only `Platform` elements**, but real LevelDesc files also carry `MovingPlatform`. Chosen: a uniform recursive walk (decision D2) in which any non-`Asset` element is a transform node, covering both without a whitelist.
10. **Two `Background`-shaped types would have collided**, the LevelDesc background element and the library entry. Chosen: rename the operations one to `LibraryBackground`.
